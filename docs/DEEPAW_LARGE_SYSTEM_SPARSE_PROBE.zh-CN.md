# DeePAW 大体系移位稀疏 Probe 重建方法

## 1. 目标与适用范围

DeePAW-eSCN 将实空间网格点作为 probe，在完整原子结构产生的等变表示上查询电荷密度。对于大晶胞，一次性查询全部密网格会产生很高的峰值显存和返回数据量。

本文给出一种不裁切晶胞的分解方法：

- 始终保留完整晶胞、全部原子和三维周期性；
- 每次只查询一个均匀稀疏子网格；
- 通过整体平移所有原子，使固定稀疏 probe 对应密网格的不同余数类；
- 将所有返回结果交错写回目标密网格。

该方法只分解 probe，不分解原子结构，因此不会引入裁切子晶胞造成的伪周期环境、边界接缝或原子图变化。

它解决的是 **DeePAW 密度推理的峰值 probe 网格开销**。它不解决后续 HALF 中全部占据波函数、全局正交化和本征求解的尺度瓶颈。

## 2. 数学原理

设目标密网格为

\[
N=(N_x,N_y,N_z),
\]

选择能整除各方向网格数的整数 stride

\[
S=(S_x,S_y,S_z),\qquad N_i\bmod S_i=0.
\]

每次 API 请求使用的稀疏网格为

\[
N^{\mathrm{sparse}}=
\left(\frac{N_x}{S_x},\frac{N_y}{S_y},\frac{N_z}{S_z}\right).
\]

对每个余数

\[
r=(r_x,r_y,r_z),\qquad 0\le r_i<S_i,
\]

将所有原子整体移动

\[
\Delta_r=
\frac{r_x}{N_x}\mathbf a_1+
\frac{r_y}{N_y}\mathbf a_2+
\frac{r_z}{N_z}\mathbf a_3,
\]

实际传给 DeePAW 的原子位置为

\[
R'_a=R_a-\Delta_r.
\]

负号是必要的。由平移协变性，

\[
\rho_{R-\Delta}(x)=\rho_R(x+\Delta),
\]

因此该请求返回的数据应写入密网格索引

\[
(r_x+S_xj_x,\ r_y+S_yj_y,\ r_z+S_zj_z).
\]

所有余数类的数量为

\[
N_{\mathrm{request}}=S_xS_yS_z.
\]

单次请求的 probe 数降低相同倍数，但总 probe 数不变。

## 3. 标准工作流

1. 从目标 CHGCAR 或 FFT 设置确定最终密网格 `Nx, Ny, Nz`。
2. 根据服务端单请求网格上限选择 stride，并保证每个方向可以整除。
3. 每个请求都使用相同的完整晶胞、元素、原子数和 `[true,true,true]` PBC。
4. 枚举所有余数 `rx, ry, rz`。
5. 按上述公式对所有原子施加相同的负位移。
6. 请求 `Nx/Sx × Ny/Sy × Nz/Sz` 稀疏网格。
7. 将返回值交错写入对应的密网格余数类。
8. 所有子网格组装完成后，再执行一次全局电子数归一化。
9. 保留模型给出的负密度，不得逐子网格截断或重新归一化。
10. 输出前检查全部网格点已填充、数值有限、电子数和轴顺序正确。

伪代码如下：

```python
rho = empty((Nx, Ny, Nz))

for rx in range(Sx):
    for ry in range(Sy):
        for rz in range(Sz):
            delta = (rx / Nx) * a1 + (ry / Ny) * a2 + (rz / Nz) * a3
            shifted_positions = positions - delta

            sparse = deepaw_predict(
                cell=cell,
                positions=shifted_positions,
                pbc=[True, True, True],
                grid=(Nx // Sx, Ny // Sy, Nz // Sz),
            )

            rho[rx::Sx, ry::Sy, rz::Sz] = sparse

rho = normalize_once_globally(rho)
```

## 4. 已完成的 Si 数值验证

### 4.1 `60³` 密网格重建

使用 Si 测试结构，将一次 `60×60×60` 推理与八次移位 `30×30×30` 推理进行比较：

| 指标 | 结果 |
|---|---:|
| 目标密网格 | `60³` |
| stride | `2×2×2` |
| 请求数 | 8 |
| 每次稀疏网格 | `30³` |
| 最大绝对误差 | `2.4760×10⁻³` |
| MAE | `6.7893×10⁻⁵` |
| RMSE | `1.2509×10⁻⁴` |
| 相对 L1 误差 | `3.4158×10⁻⁴` |
| 单体密度均值 | `0.1982302517` |
| 交错重建密度均值 | `0.1982303560` |
| 均值差 | `1.0431×10⁻⁷` |
| 单体推理耗时 | `9.5656 s` |
| 八次稀疏请求总耗时 | `9.5246 s` |

峰值 probe 数降低 8 倍。重建结果与单体预测非常接近，但不是逐位一致，因此仍须通过后续 HALF 能量、能带以及 VASP SCF 验证。

正向移动原子的相对 L1 误差约为 `0.428`，说明原子平移必须使用负号。

### 4.2 pyRho Fourier 插值测试

进一步测试了是否可以只保留稀疏 probe，再使用 Materials Project pyRho 的 Fourier interpolation 恢复 `60³` 密度。pyRho 的实现对稀疏数组做 FFT，在目标频谱中零填充，再做逆 FFT；因此它是周期带限插值，而不是缺失高频信息的学习式恢复。

测试比较了：

1. 8 个 `30³` 移位子网格直接交错；
2. 单个移位 `30³` 子网格经 pyRho 放大到 `60³`；
3. 8 个子网格分别进行相位对齐的 pyRho 插值后取平均；
4. 从同一个 `60³` 参考密度精确抽稀后再做 pyRho 的控制组。

| 方法 | 相对 L1 | RMSE | 稀疏 Nyquist 外高频保留率 |
|---|---:|---:|---:|
| 直接交错 | `3.4168×10⁻⁴` | `1.2543×10⁻⁴` | `99.75%` |
| 单个移位网格 + pyRho | `5.49–5.63×10⁻⁴` | 约 `2.14×10⁻⁴` | 不可恢复 |
| 8 个 pyRho 插值平均 | `4.1815×10⁻⁴` | `1.5570×10⁻⁴` | 约 `0%` |
| 参考密度抽稀 + pyRho | `5.2054×10⁻⁴` | `2.1058×10⁻⁴` | 约 `0%` |

合成周期函数测试同时证明：当真实密度严格限制在稀疏网格 Nyquist 范围内时，移位和相位对齐后的 pyRho 插值可达到机器精度；一旦包含更高频 Fourier 分量，直接交错仍能精确保留采样值，而 pyRho 必然丢失该部分。

因此 pyRho 可以作为一种**有损、少请求模式**：只进行一个或少数移位请求，获得平滑近似密度。但当所有余数子网格已经计算完成时，应直接交错，不应先分别 FFT 再平均。用于正式 CHGCAR 前，pyRho 模式必须独立通过电子数、负密度、HALF 能量/能带和 VASP SCF 检验。

### 4.3 约 60 Å Si 大体系试验

平衡晶格常数下构造了金刚石 Si `11×11×11` 常规胞：

- 晶胞：`59.73×59.73×59.73 Å³`；
- 原子数：10,648；
- 目标密网格：约 `660³`；
- 建议 stride：`6×6×6`；
- 每次稀疏网格：`110³`，即 1,331,000 个 probe；
- 总请求数：216。

当前 BHP6K eSCN 服务在进入推理前拒绝了该结构：

```text
原子数超过限制: 10648 > 10000
```

为单独验证 60 Å 尺度承载能力，又构造了一个 8000 原子的 `60×60×60 Å³` 测试体。该结构由 `10×10×10` 常规胞均匀拉伸得到，只用于 API 规模测试，不作为 Si 物理结果。

一个 `110³` 余数子网格的实测结果为：

| 指标 | 结果 |
|---|---:|
| 原子数 | 8000 |
| probe 数 | 1,331,000 |
| 推理耗时 | `117.323 s` |
| 密度最小值 | `-0.1648465` |
| 密度最大值 | `0.4637135` |
| 密度均值 | `0.1498681` |
| 负密度点数 | 5000 |
| 数值有限性 | 全部 finite |

结果证明完整 60 Å 晶胞和百万级稀疏 probe 可以进入当前服务，但也暴露出新的效率问题：每个余数请求都会重复计算同一个大体系的原子图和原子表示。按当前单服务串行执行 216 次约需 7 小时。

### 4.4 Probe 大小与推理效率

在相同的 8000 原子、60 Å Si 测试体和同一 GPU 服务上，固定结构和 residue，仅改变立方 probe 网格：

| Probe 网格 | 点数 | 请求耗时 | 吞吐率 |
|---|---:|---:|---:|
| `30³` | 27,000 | `3.10 s` | 8,723 points/s |
| `40³` | 64,000 | `6.52 s` | 9,812 points/s |
| `55³` | 166,375 | `15.37 s` | 10,828 points/s |
| `70³` | 343,000 | `31.11 s` | 11,024 points/s |
| `85³` | 614,125 | `55.21 s` | 11,124 points/s |
| `110³` | 1,331,000 | `119.41 s` | 11,146 points/s |

线性拟合为

```text
t[s] = 0.6233 + 8.9168e-5 * Nprobe
R² = 0.9999896
```

因此 `110³ -> 55³` 使单次请求加速 `7.77×`，接近点数减少 8 倍的理想比例。但若目标仍为完整 `660³` 密网格，`110³` 需要 216 个 residue，而 `55³` 需要 1728 个 residue。估算串行总耗时分别为 `7.16 h` 和 `7.38 h`；较小请求并不减少总 GPU 工作量，只降低单请求峰值内存并提供更细的并行任务粒度。

此外，`30³` 和 `40³` 的平均密度已经明显偏离 `55³–110³` 的稳定值。因此不能只根据速度选择 probe 大小，必须同时检查密度积分、负密度、空间误差以及下游 HALF/VASP 结果。

## 5. 生产化所需改进

### 5.1 提高原子数上限

当前服务上限是 10,000 个原子。未拉伸的约 60 Å 平衡 Si 需要至少 10,648 个原子，因此生产设置建议留有余量，例如提高到 12,000 或更高，并重新测试 GPU 峰值显存。

### 5.2 缓存与 probe 解耦

最关键的改进是把一次请求拆成两阶段：

1. 对完整结构只计算一次邻居图、原子 embedding 或可供解码的系数；
2. 不同余数请求只改变 probe 坐标并执行密度解码。

理想接口形式为：

```text
structure -> cached atomic representation / coefficients
probe coordinates + cache handle -> density values
```

这可以避免 216 次重复原子图推理。不同余数还可以分发到多张 GPU 并行解码。

### 5.3 可恢复执行

大批次应逐余数保存：

- residue 索引；
- 原子位移；
- 稀疏网格 shape；
- 密度数组及 SHA256；
- 服务端模型与 checkpoint 标识；
- 耗时、有限性、最小值、最大值和积分电子数。

中断后只补算缺失或校验失败的 residue，最后再组装密网格。

## 6. 方法边界

该方法不能解决以下问题：

- HALF 对全部占据态的波函数存储；
- 全局 PAW overlap 正交化；
- `NBANDS×NBANDS` 或 `2NBANDS×2NBANDS` 投影问题；
- 大体系完整能带求解；
- 由本征态数量导致的二次或三次标度。

因此完整的大体系路线应分为两层：

```text
DeePAW 大体系密度：移位稀疏 probe + 原子表示缓存
HALF 大体系电子结构：随机密度矩阵/Green's function + 确定性活性区
```

第一层已经得到数值验证；第二层仍需独立原型和与现有确定性 HALF 的严格对照。
